# SEO Architecture — NiceModels.ch

Notes for developers working on metadata, routing or the sitemap.

---

## German-canonical strategy

The site is primarily Swiss German. There are no locale-prefixed URLs (`/de/`, `/fr/`, etc.); every canonical URL points to the German version. The `hreflang` block on each page is:

```
de-CH → the page URL
x-default → the page URL (same)
```

The interface is translated with `next-intl` (the locale comes from a cookie, not the URL), but search engines see one canonical German URL per page.

Add locale-prefixed alternate URLs only together with fully localised content at those URLs. Hreflang alternates that point to identical content are worse than none.

## Central metadata helper — `src/lib/seo.ts`

All static and most dynamic pages generate metadata via `buildMetadata()`:

```typescript
import { buildMetadata } from '@/lib/seo'

export const metadata = buildMetadata({
  path: '/some-route',          // relative path — canonical is built from this
  title: 'Page Title',          // without '| NiceModels.ch'; the template adds it
  description: 'Under 155 chars.',
  ogImage: '/custom.webp',      // optional; defaults to /logo.webp
  ogType: 'article',            // optional; defaults to 'website'
})
```

`buildMetadata()` emits:
- `title` (string; root layout template appends `| NiceModels.ch`)
- `description`
- `alternates.canonical` (absolute URL)
- `alternates.languages` (`de-CH` + `x-default` pointing to the same canonical)
- `openGraph` with `siteName`, `locale`, `type`, `url`, `images`
- `twitter` card

**Title template**: the root layout (`src/app/layout.tsx`) sets `title: { template: '%s | NiceModels.ch' }`, so titles passed to `buildMetadata()` must not contain `| NiceModels.ch`. `/terms` passes `'AGB'` and renders as `'AGB | NiceModels.ch'`.

## Per-page metadata — dynamic routes

Dynamic pages (`/models/[id]`, `/clubs/[id]`, `/jobs-rents/[id]`, `/blog/[slug]`) export their own `generateMetadata()`, because they need per-item data. Each one sets:
- `alternates.canonical`
- `alternates.languages` (`de-CH` + `x-default`), except `/blog/[slug]`, which has no translated content
- `openGraph` with the matching `type` (`'profile'`, `'article'`, etc.)
- a `twitter` card

A page's `openGraph` object replaces the root layout's entirely (there is no deep merge), so every page that emits Open Graph data sets `siteName` and `locale` itself.

---

## Legacy profile URLs

`/profile/[id]` is a legacy URL. It redirects permanently (308) to `/models/[id]` through `redirects()` in `next.config.ts`, so old links and indexed URLs pass to the canonical model page.

## City pages — `src/app/escort/`

### Structure

```
src/app/escort/
  page.tsx          — /escort (city index, static)
  [city]/
    page.tsx        — /escort/:city (dynamic but statically pre-rendered)
src/lib/data/
  cities-seo.ts     — single source of truth for city config
```

### `cities-seo.ts` fields

| Field | Purpose |
|-------|---------|
| `slug` | URL segment, e.g. `'zurich'` |
| `labelDe` | Display name, e.g. `'Zürich'` |
| `canton` | Canton abbreviation, e.g. `'ZH'` |
| `dbCityName` | Exact value in `model_details.city` DB column |
| `dbAreaName` | Exact value in `club_details.area` DB column |
| `introCopyDe` | ~350-word intro copy, `\n\n` separates paragraphs |
| `relatedCitySlugs` | Array of 3–4 slugs to show in "Related cities" section |

### Adding a new city

1. Look up the exact values of `model_details.city` and `club_details.area` in the database.
2. Write a ~350-word German intro text (factual, no explicit content).
3. Add a `CityConfig` entry to the `CITIES` array in `cities-seo.ts`.
4. The sitemap is generated from `CITIES` automatically — no sitemap changes needed.
5. Run `npm run build` to confirm static generation of the new city page.

### JSON-LD on city pages

City pages render `BreadcrumbList` and `CollectionPage` in a plain `<script type="application/ld+json">` tag from the server component, not through `next/script`. `next/script` injects on the client, so crawlers that do not run JavaScript would miss the schema.

## JSON-LD inventory

| URL pattern | Schema type | Location |
|------------|-------------|----------|
| All pages | `WebSite` | `src/app/layout.tsx` inline `<script>` |
| `/escort/[city]` | `BreadcrumbList`, `CollectionPage` | `src/app/escort/[city]/page.tsx` inline `<script>` |
| `/jobs-rents/[id]` (job listings only) | `JobPosting` | `src/app/jobs-rents/[id]/page.tsx` inline `<script>` |
| `/blog/[slug]` | `DiscussionForumPosting` | `src/app/blog/[slug]/page.tsx` inline `<script>` |

## robots.ts — `src/app/robots.ts`

`/robots.txt` is generated by `src/app/robots.ts`. Current rules:

- `User-Agent: *` — allows `/`, disallows all private paths (dashboard, API, auth, chat, etc.)
- 10 AI bots blocked entirely: GPTBot, ClaudeBot, Claude-Web, anthropic-ai, PerplexityBot, CCBot, Google-Extended, OAI-SearchBot, Bytespider, Amazonbot

To add a new AI bot, add its user agent string to the `AI_BOTS` array in `src/app/robots.ts`.

To add a new private path, add it to the `disallow` array in the wildcard rule.

---

## sitemap.ts — `src/app/sitemap.ts`

`/sitemap.xml` is generated by `src/app/sitemap.ts`. Three sections:

1. **Static pages** — hardcoded URLs with `STATIC_LASTMOD = new Date('2026-06-11')`. Update `STATIC_LASTMOD` when static content changes.
2. **City pages** — generated from the `CITIES` array (`/escort` + 10 city slugs). Priority `0.8`, `changeFrequency: 'weekly'`.
3. **Dynamic entries** — models, clubs, job listings, blog topics fetched from Supabase with real DB timestamps. Only active/public entries are included.

Do not use `new Date()` as `lastmod` for static pages: every rebuild would mark them as changed and trigger needless re-crawls.

## Age gate — `src/components/AgeGate.tsx`

The 18+ gate is a `'use client'` component added to `src/app/layout.tsx`. It:

1. Starts with `useState(false)`, so the server render contains no gate and crawlers see the full page
2. Reads the `age_verified` cookie in `useEffect` (client-only)
3. Shows the gate overlay only if the cookie is absent
4. Sets `age_verified=true` cookie (60-day expiry, `SameSite=Lax; Secure`) on "Ja, ich bin 18+"
5. Is not shown on: `/dashboard`, `/auth`, `/login`, `/register`, `/onboarding`, `/forgot-password`, `/reset-password`, `/chat`

Keep AgeGate a client component. Reading the cookie on the server would render the gate instead of the content for crawlers.

## CSP — `next.config.ts`

The Content Security Policy is sent as `Content-Security-Policy-Report-Only`, so it is not enforced yet. Once the browser console shows no violations on the key pages:

1. Change `'Content-Security-Policy-Report-Only'` → `'Content-Security-Policy'` in `next.config.ts`
2. Redeploy
3. Monitor for 24 hours

Add any new third-party domain (CDN, analytics, etc.) to the relevant directive in `next.config.ts` before enforcing.

## Deliberate choices

| Choice | Reason |
|---|---|
| `STATIC_LASTMOD` changes only when static content changes | A moving date marks unchanged pages as updated |
| JSON-LD in a plain `<script>` tag, not `next/script` | `next/script` injects on the client, so crawlers miss it |
| Root layout sets only `canonical`, no `languages` | Hreflang comes from each page through `buildMetadata()` |
| AgeGate starts hidden (`useState(false)`) | The server render, and therefore crawlers, get the content instead of the gate |
| Titles without `\| NiceModels.ch` | The root layout template appends it |
| `/profile/:id` redirects to `/models/:id` | Old links and indexed URLs keep working |
